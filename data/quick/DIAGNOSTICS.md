# Диагностика компилятора

Справочник кодов ошибок компилятора (`RECHxxxx`) - для поиска по коду,
который печатает `rech build`/`rech run`/`rech test`, не для
последовательного чтения. Про сам язык - [Руководство](MANUAL.md)/
[Спецификация](SPEC.md); здесь - только про то, ЧТО значит код и почему
сообщение выглядит именно так.

## Формат вывода

```
ошибка[RECH2001]: инструкции должны быть разделены переносом строки или ";", получено "2"
  --> файл.rech:2:22
   |
 2 |     переменная x = 1 2
   |                      ^

подсказка: ...
```

- `[RECHxxxx]` - код категории (см. таблицы ниже) - искать по нему, если
  сообщение непонятно из текста.
- `--> файл:строка[:столбец]` - место в исходнике; столбец известен не
  всегда (у части семантических проверок компилятор пока не сохраняет
  колонку, только строку - сниппет тогда без каретки `^`).
- `подсказка: ...` - печатается не всегда, только когда у компилятора есть
  однозначная, безопасная рекомендация (не для каждой категории).

`предупреждение[RECHxxxx]: ...` - в том же формате, но сборку не
останавливает (недостижимый код, `RECH3700`): программа собирается и
запускается, предупреждение печатается рядом.

Если независимых ошибок за один прогон несколько (в разных функциях/
сущностях/файлах), `rech build` печатает **все** сразу, не только первую, с
итоговой сводкой `N ошибок` в конце.

## Коды - по категориям, не по сообщению

Один код покрывает целую категорию однотипных по природе ошибок, а не одно
конкретное сообщение - как `E0308` в Rust покрывает любое несовпадение
типов, а не отдельный код на каждую пару типов. Два по-разному
сформулированных сообщения одной природы (например, "ожидался `":"`,
получено `"="`" и "ожидался `")"`, получено `";"` в разных местах грамматики
могут делить один и тот же код.

## RECH1xxx - лексер

Ошибки на уровне текста исходника, до попытки понять его как программу.

| Код | Категория |
|---|---|
| `RECH1001` | Неожиданный символ - не входит ни в один токен языка. |
| `RECH1002` | Незакрытый комментарий (`/* ...` или `/** ...` без `*/`). |
| `RECH1003` | Литерал не закрыт или некорректен - строка/символ/`` ` ``-строка без закрывающей кавычки, перенос строки внутри `"..."`/`'...'`, пустой `'...'`, символьный литерал длиннее одного символа. |
| `RECH1004` | Неизвестная последовательность экранирования (`\X`, где `X` не входит в поддерживаемый набор). |
| `RECH1005` | Исходный файл не в UTF-8 или не в нормализованной форме Unicode NFC (частая причина NFC - буква "ё", набранная как "е" с отдельным диакритическим знаком). |
| `RECH1006` | Комментарий (`//` или `/*`) внутри вставки `${...}` шаблонной строки - вставка часть строки; пояснение пишется после закрывающей `` ` ``. |

## RECH2xxx - парсер

Текст синтаксически не является программой на Rech - грамматика, не смысл.

| Код | Категория |
|---|---|
| `RECH2001` | Неожиданный токен / общее несовпадение ожидаемой грамматики. |
| `RECH2002` | Не хватает обязательного токена после ключевого слова/имени (например, `(` после имени метода). |
| `RECH2003` | Незакрытая скобка/висячая запятая перед закрывающей скобкой без переноса строки. |
| `RECH2004` | Модификатор (`приватный`/`новая`/`статический`/...) не согласован по роду/числу со словом, к которому относится - ожидаемая форма обычно в подсказке. |
| `RECH2005` | Повторное объявление там, где допустимо только одно (конструктор дважды, параметр типа дважды и т.п.). |
| `RECH2006` | Нарушение ограничений точки входа (`главная`) - параметры/тип результата/`асинхронная`/`экспортировать` у неё не допускаются. |
| `RECH2007` | Падежное сопоставление аргументов естественного вызова - неоднозначная/лишняя/недостающая словоформа. |
| `RECH2008` | Нарушение правил `экспортировать` (список экспорта, экспорт конструктора/метода). |
| `RECH2009` | Нарушение инварианта сущности/структуры/перечисления/перегрузки оператора (например, перегрузка оператора не с двумя параметрами). |
| `RECH2010` | `этот`/`родитель(...)` вне допустимого контекста (не внутри тела метода/конструктора). |
| `RECH2011` | Нарушение ограничения на уровне инструкции (`переменная` без значения или с `: Тип` - явный тип пишется `Тип имя`; доступ к полю не как инструкция, и т.п.). |
| `RECH2012` | Некорректный литерал (числовой литерал не разбирается). |
| `RECH2013` | Ошибка в блоке условной компиляции (`#если`/`#иначе`). |
| `RECH2014` | Ошибка в `выбрать`/`когда` (пустая ветка, повторное `иначе`, не найдена закрывающая `}`). |
| `RECH2015` | Ошибка в шаблонном литерале (`` `...${...}...` ``). |

## RECH3xxx - семантика

Программа синтаксически корректна, но нарушает правила языка (типы, имена,
видимость). Первые два кода - сквозные (встречаются в любой из тем ниже),
остальные - по теме.

| Код | Категория |
|---|---|
| `RECH3001` | Необъявленное имя - переменная/функция/тип/метод/поле. При похожем объявленном имени рядом - подсказка "возможно, имелось в виду ...". |
| `RECH3002` | Повторное объявление там, где допустимо только одно (сущность/функция/интерфейс/поле/константа дважды). |
| `RECH3101` | Несовпадение типов - там, где нужно явное приведение (`(Строка)` и т.п.). |
| `RECH3110` | Разрешение имени типа/generic-коллекции (`Словарь<...>` с неверным числом параметров и т.п.). |
| `RECH3120` | Тип переменной `переменная имя = значение` не вычислить из значения (`Ничто`, пустой `[]`, список только из `Ничто`) - в подсказке та же строка с явным типом: `?Тип имя = ...`. |
| `RECH3130` | Проверка на уровне инструкции (тип объявленной переменной не совпадает со значением, `вывести`/`показать` nullable без разворачивания, и т.п.). |
| `RECH3140` | Проверка на уровне выражения/встроенной функции/оператора - самая широкая категория (аргументы builtin-функций, доступ к полю не сущности, `"+"` без явного приведения строки, и т.п.). |
| `RECH3210` | Объявление сущности/структуры/функции верхнего уровня (зарезервированное имя, конфликт с производным типом состояния, недопустимая перегрузка). |
| `RECH3220` | Объявление интерфейса (дубль метода, не найден базовый интерфейс). |
| `RECH3230` | Наследование/переопределение. |
| `RECH3320` | Nullable-тип (`?Тип`) - двойное `??`, `?` без имени типа. |
| `RECH3330` | Указатель (`Указатель<T>`) - в т.ч. указатель на nullable-тип. |
| `RECH3335` | Массив фиксированной длины (`T[N]`) - длина 0, недопустимый тип элемента, константный индекс вне границ, запись в массив, который не переменная/поле/элемент. |
| `RECH3340` | Состояния/`противоположность` (метод-антоним для `становится`). |
| `RECH3401` | Generics - параметр типа объявлен дважды, ограничение не выполнено. |
| `RECH3430` | Тип `Вызываемый(...)` - несовпадение сигнатуры лямбды/захвата. |
| `RECH3510` | Исключения - `поймать(...)` требует сущность-наследника `Исключение`, тип перечислен дважды. |
| `RECH3610` | Семантика `экспортировать`/внешних объявлений - тип без стабильного C-представления, метод экспортирован без экспорта сущности. |
| `RECH3700` | Анализ потока управления - недостижимый код (предупреждение), не все пути функции возвращают значение. |
| `RECH3801` | Цель JSON/XML/YAML/PROTOBUF/строки БД - неподдержанный тип для `разобрать`/`сериализовать`/результата запроса. |
| `RECH3910` | Вычисление константы/значения по умолчанию поля/параметра. |
| `RECH3990` | Прочая семантическая проверка (индексация `[]`, литерал списка, тернарный оператор, `выбрать` по значению, перегрузка функций и т.п. - темы с одной-двумя проверками, не выделенные в отдельный код). |

## RECH9000 - компилятор

```
ошибка[RECH9000]: <текст от cbackend/системного компилятора C>
```

Не ошибка в вашей программе - нарушенный внутренний инвариант самого
компилятора Rech (то, что генератор C-кода или системный `cc`/`clang`
считает невозможным) или сбой самой сборки (не найден `cc`, компоновщик
вернул ошибку). Если видите этот код на программе, которая не делает
ничего экзотического - вероятно, баг компилятора, стоит сообщить о нём
вместе с исходником.
