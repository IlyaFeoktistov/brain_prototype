# Морфология: падежи, согласование, естественный синтаксис

В Rech грамматика русского языка - часть синтаксиса, а не оформление
поверх него. Эта страница собирает в одном месте все правила, где форма
слова (падеж, род, число) на что-то влияет: как объявить параметр с
падежной ролью, как вызвать функцию или метод без скобок, как правильно
согласовать `новый`/`приватный`/`статический` с именем сущности или поля,
и как устроены переходы состояний через полные формы причастий.

Движок понимает не произвольный русский текст, а конечный, известный на
этапе компиляции словарь - идентификаторы вашей программы (сущности,
переменные, параметры, методы) плюс стандартную библиотеку. Если слово не
укладывается в правило (например, род на `-ь` неоднозначен - `пароль`
мужского рода, `дверь` - женского), компилятор об этом сообщает ошибкой
компиляции, а не угадывает - см. "Когда нужно вмешаться" в конце страницы.

## Падежные роли параметров

Параметр функции или метода может объявить падежную роль - тогда при
**естественном вызове** (ниже) словоформа-аргумент находит свой параметр
по падежу, а не по позиции:

| слово         | падеж                          | обязательный предлог |
|---------------|--------------------------------|-----------------------|
| `кто`         | именительный                   | -                     |
| `кого`        | винительный, одушевлённый      | -                     |
| `кому`        | дательный                      | -                     |
| `кем`         | творительный                   | -                     |
| `что`         | винительный, неодушевлённый    | -                     |
| `чему`        | дательный, неодушевлённый      | -                     |
| `чем`         | творительный, неодушевлённый   | -                     |
| `где`         | предложный                     | -                     |
| `с кем`/`с_кем`       | творительный, одушевлённый | `с`              |
| `с чем`/`с_чем`       | творительный, неодушевлённый | `с`            |
| `для кого`/`для_кого` | родительный, одушевлённый  | `для`            |
| `для чего`/`для_чего` | родительный, неодушевлённый | `для`           |
| `куда`        | винительный                    | `в`                   |
| `откуда`      | родительный                    | `от`/`из`             |

Слова из одной строки-пары (например `кого`/`что`, `кому`/`чему`,
`куда`/`для чего`) делят один падеж и взаимоисключающи - у одной функции
не может быть двух параметров с одинаковой падежной ролью. Параметр
объявляется одной из трёх форм:

```
функция оформить(кого: Пользователь)                     // падежное слово - и роль, и имя параметра
функция оформить(кого пользователь: Пользователь)        // роль отдельно от имени в теле функции
функция оформить(результат: Строка)                       // без падежной роли - только по позиции
```

## Естественный вызов функции

```
поприветствовать пользователя в системе
```

- то же самое, что `поприветствовать(пользователь, система)`, без скобок и
  без фиксированного порядка слов - падеж каждого аргумента сам определяет,
  какому параметру он достанется. Предлог перед аргументом (`в`, `с`) не
  обязателен и не влияет на сопоставление - его можно опустить, падеж
  работает и без него.
- Аргумент - **только** идентификатор уже объявленной переменной (обычной
  или параметра, или переменной цикла `для`), зарегистрированной как
  существительное. Литералы (`1`, `"текст"`) не подходят - у них нет
  словоформы.
- Сопоставление - в два прохода: сначала аргументы связываются с ещё не
  занятыми падежными параметрами (порядок слов свободен), затем оставшиеся
  аргументы заполняют по порядку написания параметры без падежной роли
  (здесь порядок уже важен, падеж не проверяется).
- Падежный параметр, не получивший подходящего по падежу аргумента, - это
  ошибка компиляции, а не "на что осталось".
- Имя функции пишется ровно так, как оно объявлено - спряжение не
  распознаётся (`функция зарегистрировать(...)` вызывается только как
  `зарегистрировать ...`).
- Вся фраза должна умещаться в одну строку.
- Разбирается только как самостоятельная инструкция - если нужен результат
  как значение (правая часть `=`, аргумент другого вызова, `вывести ...`),
  естественный вызов тоже подходит, но фраза не может быть частью более
  крупного выражения (например, нельзя написать `1 + поприветствовать
  пользователя`).

Пример (`examples/функции/естественный_вызов.rech`,
`examples/функции/падежные_роли.rech`):

```
функция поприветствовать(кого: Строка, где: Строка)
{
    вывести "Привет, " + кого + "! Добро пожаловать в " + где
}

функция главная
{
    переменная пользователь = "Илья"
    переменная система = "чат"

    поприветствовать пользователя в системе   // "пользователя" - винительный -> "кого"
                                               // "в системе" - предложный -> "где"

    поприветствовать(пользователь, система)   // то же самое строгим вызовом
}
```

## Естественный вызов метода сущности

Тот же принцип работает и для методов - слева от имени метода стоит
получатель (`этот` или переменная/параметр известного сущностного типа),
справа - имя метода ровно как оно объявлено (без спряжения, тот же принцип,
что и у свободных функций), затем падежные аргументы:

```
пользователь авторизовать паролем
книга выдать
```

Строгий вызов (`пользователь.авторизовать(пароль)`) остаётся рабочим
всегда - оба синтаксиса доступны одновременно, выбор за автором кода.
Получателем может быть локальная переменная, параметр другого метода/
функции или `этот` внутри тела метода того же типа.

Примеры - `examples/сущности/естественный_вызов_метода.rech`,
`examples/сущности/естественный_вызов_метода_падежи.rech`,
`examples/сущности/естественный_вызов_метода_параметр.rech`.

## Деепричастный вызов

```
сложив(2, 3)
    вывести результат
    вывести результат * 2
```

Альтернатива обычному вызову функции с объявленным типом результата: без
скобок и присваивания, с блоком инструкций **большего отступа** вместо
фигурных скобок - внутри блока доступна переменная `результат`. Деепричастная
форма имени функции определяется автоматически (`сложить` -> `сложив`,
`создать` -> `создав`) или явным тегом
`` `деепричастие:слово` `` после типа результата, если автоматическое
определение не сработало или дало не ту форму:

```
функция необычно_названная_функция(а: Целое): Целое `деепричастие:почудив`
{
    вернуть а * 1000
}
```

Блок заканчивается на первой инструкции, чей отступ не больше отступа
самого деепричастия; вложенный деепричастный вызов временно затеняет
внешний `результат`, снова становящийся видимым после его блока. Пример -
`examples/функции/деепричастие.rech`.

## Согласование по роду и числу

Несколько мест в языке требуют, чтобы ключевое слово согласовывалось с
родом/числом сущности или поля, к которому оно относится - как в обычной
русской речи.

### Создание экземпляра

`новый`/`новая`/`новое`/`новые` перед именем сущности - форма зависит от
рода и числа самого имени:

```
новый Пользователь(...)   // мужской род
новая Сова(...)           // женский род
новое Окно(...)           // средний род
новые Права(...)          // множественное число
```

Неверная форма для сущности с известным родом/числом - ошибка компиляции.
Если род/число определить не удалось - проверка согласования пропускается,
принимается любая из четырёх форм.

### Видимость поля

`приватный`/`публичный`/`защищённый` перед полем в `имеет:` согласуется по
роду и числу с ТИПОМ поля, как прилагательное с главным словом ("широкая
река Волга") и как `новая Точка(...)`. Род берётся у внешнего типа (`Список`
у `Список<Строка>`, `Строка` у `?Строка`, `Целое` у `Целое32`); у параметра
типа (`T`) проверки нет. Переименование поля модификатор не затрагивает:

```
имеет:
    приватная Строка пароль
    приватная Строка почта
    приватная Строка имя
    приватный Список<Строка> права
```

Метод, в отличие от поля, называется глаголом - у него нет рода, поэтому
модификатор видимости перед методом допустим только в форме мужского рода
(`приватный отправить(...)`, не `приватная отправить(...)`), любая другая
форма - ошибка компиляции.

### Статические члены

`статический`/`статическая`/`статическое`/`статические` перед полем -
согласуется тем же принципом, что и видимость (порядок при сочетании с
видимостью любой: `статический приватный` и `приватный статический`).
Перед статическим методом - тоже только мужская форма, как и у обычного
метода.

### Абстрактные сущности

`абстрактная сущность Имя { ... }` / `абстрактный класс Имя { ... }` -
модификатор согласуется с самим ключевым словом (`сущность`/`класс`), не с
именем типа: всегда `абстрактная сущность`, но `абстрактный класс`,
независимо от рода `Имя`.

### `наследует`/`реализует` - винительный падеж

Слово после `наследует`/`реализует` пишется в винительном падеже - оба
слова управляют винительным падежом, как и полагается по-русски, а не
берутся словарной формой как ключевые слова:

```
сущность Сотрудник наследует Пользователя   // не "Пользователь"
сущность Штука реализует Отправителя        // не "Отправитель"
```

Для многих слов (неодушевлённых, среднего рода, причастий вроде
`Звучащий`) винительный падеж совпадает с именительным, визуальной разницы
нет. Имя вне покрытия словаря - принимается как написано (permissive
fallback).

## Состояния и переход через полную форму

`состояние: слово1 слово2 ...` в объявлении сущности задаёт конечный набор
состояний - каждое слово либо краткая форма страдательного причастия/
краткого прилагательного на "-н"/"-т" (`авторизован`, `закрыт`), либо
действительное причастие прошедшего времени известного глагола
(`вошедший` - от `войти`). Для каждого слова компилятор синтезирует
производный тип - полную форму, согласованную по роду с самой сущностью,
плюс имя сущности:

| состояние | сущность (жен./муж./ср. род) | производный тип |
|---|---|---|
| `авторизован` | `Пользователь` (муж.) | `АвторизованныйПользователь` |
| `авторизован` | `Система` (жен.) | `АвторизованнаяСистема` |
| `вошедший` | `Сотрудница` (жен.) | `ВошедшаяСотрудница` |

Переход в состояние - `<получатель> становится <полная форма>`, причём
форма должна быть в **творительном падеже** (русское "стать X" управляет
творительным):

```
пользователь становится авторизованным   // муж. род
система становится авторизованной        // жен. род
```

Компилятор сверяет написанную форму с ожидаемой для каждого объявленного
состояния сущности-получателя - несовпадение (в том числе попытка
написать краткую форму вместо полной) - ошибка компиляции с подсказкой
ожидаемой формы. Функция, принимающая параметр производного типа
(`п: АвторизованныйПользователь`), может быть вызвана только со
значением, для которого компилятор способен доказать переход через
`становится` на всех путях выполнения - иначе вставляется рантайм-проверка,
бросающая исключение при несовпадении.

Примеры - `examples/сущности/причастие.rech`,
`examples/сущности/глагольные_семьи.rech`.

## Когда нужно вмешаться

Словарь языка выводит род/число/одушевлённость идентификаторов
автоматически по правилам склонения - но для некоторых слов формального
правила недостаточно:

- **Род слов на `-ь`** не определяется окончанием (`пароль` - мужской,
  `дверь` - женский) - если слово не входит во встроенный словарь
  исключений, компилятор требует явной регистрации рода, а не угадывает.
- **Одушевлённость** не следует из окончания вообще (`пользователь` -
  одушевлённое, `документ` - нет) - у сущностей выводится по умолчанию как
  "одушевлённое"; для сущности, обозначающей вещь, нужна аннотация
  `неодушевлённое`.

В обоих случаях компилятор останавливается с понятной ошибкой вместо
того, чтобы угадать неверную форму - если вы видите такую ошибку у
собственного идентификатора, это ожидаемое поведение, а не баг: язык
сознательно не пытается быть полным морфологическим анализатором русского
языка, только точным и предсказуемым для словаря вашей программы.
